## 1. Sample Reverse Engineering — "2~3초 안에 이해되는" 이유

샘플이 제목을 읽기 전에 주제가 인식되는 이유는 **"오브젝트 나열"이 아니라 "문장 구조"**이기 때문이다.

- **주어(Hero Subject)**: 흰 셔츠 + 랜야드 회사원 캐릭터가 "무언가를 들고/가리키는" 동작을 한다 → 주체와 행위가 고정됨.
- **목적어(Hero Object)**: 캐릭터가 든 오브젝트(돈봉투/타블렛)가 개념의 "결과물"이다 → 돈을 받는 상황.
- **보어(Supporting Objects)**: 달력(시기)·시계(시간)·문서(근거)·계산기(계산)가 Hero를 설명하는 클러스터.
- **접속사(색 코드)**: 오렌지 halo = 행동/활기, 파랑 = 신뢰/정산 → 감정 톤까지 전달.
- **마침표(구도)**: 오렌지 원이 시선을 중앙에 고정 → 2~3초 안에 "사람이 돈 관련 정산을 한다"가 읽힘.

즉, **"하나의 장면(Scene)"으로 개념을 동사화**하는 것이 샘플의 핵심 디자인 원리다. 단순 아이콘 조합(현재 접근)은 이 "동사"가 없다.

### 세부 역분석 10항

| # | 항목 | 분석 |
|---|------|------|
| 1 | Hero Subject | 흰 셔츠+랜야드 캐릭터 (미소, 엄지척/포인팅). 중앙 또는 중앙-측면. |
| 2 | Hero Object | 캐릭터가 든 것: 돈봉투/타블렛. 개념의 결과물. |
| 3 | Supporting Objects | 달력, 시계, 문서(+돋보기), 돈/동전, 계산기, 차트 — 5~8개 |
| 4 | 정보 계층 | Hero(1순위) > Supporting(2순위) > 데코(3순위). 크기·위치·채도로 계층화. |
| 5 | 시선 이동 경로 | halo 중앙 → 캐릭터 얼굴/손 → Hero Object → Supporting 링(시계방향) → 하단 전경 |
| 6 | 오브젝트 간 관계 | "시기(달력) × 시간(시계) → 계산(계산기) → 결과(돈)"의 인과 클러스터 |
| 7 | 공간 분할 | 상단 제목 존 / 중앙 halo 존 / 링 존 / 하단 전경(데스크·카드) — 4개 밴드 |
| 8 | 색상 체계 | 라이트블루 배경 + 로열블루/네이비 + 오렌지 halo + 그린/레드 포인트 + 화이트 카드 |
| 9 | 깊이감 | overlap 3겹(halo → 캐릭터 → 전경 오브젝트) + soft flat shadow |
| 10 | 제작 방식 추정 | 순수 AI 단독 가능성 낮음(좌표 정확도/일관성) → **AI 초안 + 디자이너/코드 후처리**가 가장 유력. Illustrator/SVG 템플릿 + AI 일러스트 보조 순. |

## 2. Sample Design DNA (20항 요약)

1. **스타일**: 한국형 카드뉴스/블로그 썸네일 편집 일러스트. flat 2D 벡터 + 인포그래픽 그리드 하이브리드.
2. **제작 방식 추정 (가능성 순)**: ① AI 초안 + 디자이너 후처리 ② SVG/Figma 템플릿 + AI 일러스트 보조 ③ 순수 AI ④ 코드 합성.
3. **렌더링**: 완전 flat, 단색 면 + 볼드 아웃라인, 그라데이션은 배경에만.
4. **팔레트**: 라이트 블루 BG / 로열블루·네이비 primary / 오렌지 halo accent / 그린·레드·옐로우 포인트 / 화이트 카드.
5. **명도·채도**: 고명도·중고채도, 어두운 영역 없음(헤더 바 제외), 과포화 금지.
6. **조명·그림자**: 조명 개념 없음, soft flat cast shadow 1개만.
7. **입체감**: 원근 대신 3겹 overlap + scale 차이.
8. **선**: 굵고 균일한 rounded 아웃라인(네이비/블랙), 전 모서리 rounded.
9. **캐릭터**: 2~3등신, 흰 셔츠+랜야드(브랜드 고정), 미소, 엄지척/포인팅.
10. **얼굴**: 클로즈업 없음, 단색 피부+단순 눈/미소 라인.
11. **오브젝트**: 미니어처 씬급 디테일(달력 스프링, 돋보기, 코인 리플), 흰 카드 위 "정보 단위".
12. **배경**: 심플 라이트블루 + 대형 오렌지 halo + 스파클/컨페티. 복잡한 실내 없음.
13. **정보 밀도**: 8~12 오브젝트, "풍부하지만 정돈".
14. **구도**: 4밴드(제목/halo/링/전경) + 링 배열 + 대칭 균형.
15. **focal point**: 중앙 캐릭터(손의 오브젝트), 오렌지 원이 집중 유도.
16. **여백**: 상단·측면 의도적 통풍.
17. **전문성**: 컬러 시스템+그리드+라운드+헤더/푸터 프레임의 "시리즈 템플릿" 일관성.
18. **핀테크 적합성**: 계산기/달력/서류/돈/차트 메타포 + 블루(신뢰)·오렌지(활기).
19. **고품질 핵심**: 팔레트 시스템 / 통일 라인·라운드 / 3단 레이아웃 / 오브젝트 디테일 / 캐릭터 브랜드 일관성 / 볼드 타이포.
20. **금지 요소**: 실사, 시네마틱, 복잡한 배경, AI 텍스트, 얼굴 클로즈업, 과한 그라데이션/섀도, 과포화, 무질서.

## 5. Object System (오브젝트 시스템)

**핵심 원리**: 오브젝트는 "아이콘"이 아니라 "정보 단위(미니어처 씬)"여야 한다.
- 각 오브젝트 = 흰 카드(또는 흰 바탕) 위에 올라가 독립적으로 읽힘
- 디테일 필수: 달력의 빨간 스프링/그리드, 문서의 접힘/클립/봉인, 계산기 키패드, 코인의 광택 리플
- 스타일 통일: 전 오브젝트 동일 outline 두께·동일 rounded 반경·동일 섀도 규칙

| 오브젝트 | 필수 디테일 | Hybrid v2 현재 상태 |
|----------|-------------|---------------------|
| 달력 | 스프링, 요일 헤더, 그리드, 체크/강조 | ✅ 있음(요일 헤더+그리드+체크) |
| 시계 | 베젤 2겹, 눈금, 시/분/초침 | ✅ 있음 |
| 문서 | 접힘 모서리, 헤더 밴드, 라인 굵기 변화 | ✅ 있음 |
| 세금문서 | 빨간 봉인, 헤더, 굵기 변화 | ✅ 있음 |
| 트로피 | 컵/손잡이/받침/별 | ✅ 있음(v2 신규) |
| 계산기 | 키패드 그룹, 스크린 | ✅ 있음 |
| 동전/코인스택 | 광택 리플, 그림자 | ✅ 있음 |
| 돈봉투 | **없음** | ❌ 추가 필요 |
| 차트 | baseline, 상승 화살표 | ✅ 있음 |
| 캐릭터 | **없음** | ❌ 최대 과제 |

## 8. Technical Feasibility (구현 방식 비교)

### A. PIL 직접 그리기 (현재 Hybrid v2 방식)
- 장점: 100% 재현성·결정적, 텍스트 무결성 완벽, 보호/검증 구조 기확보, 외부 의존 없음
- 단점: 캐릭터(인물) 표현 한계, 고급 일러스트 질감 한계, 오브젝트당 구현 비용
- 샘플 재현 가능성: **50~65%** (구도·색·오브젝트는 가능, 캐릭터·일러스트 감성은 한계)

### B. SVG 직접 제작
- 장점: A와 동일한 결정성 + 디자이너가 벡터 에디터로 제작 가능(질감↑), 재사용 용이
- 단점: 런타임 자산 관리 필요, 현재 저장소에 SVG 에셋 없음(0개), 제작 공수
- 샘플 재현 가능성: **60~75%** (디자이너 손길 있으면 캐릭터도 가능)

### C. Pollinations AI (현재 사용 중)
- 장점: 일러스트 질감·캐릭터 표현 최고
- 단점: 좌표/구도 제어 불가, 텍스트 오류 리스크, 시드 편차, **1024×576 해상도 캡**(1280×720 미달), 시리즈 일관성 낮음
- 샘플 재현 가능성: **30~45%** (개별 장면은 근접 가능, 템플릿 일관성은 불가)

### D. AI + SVG/PIL Hybrid (권장 후보)
- AI 담당: 배경 질감, 캐릭터, halo 주변 일러스트 보조
- 코드 담당: Hero 오브젝트, 아이콘, 배지, 레이아웃/좌표, 텍스트, 브랜드 요소, 프레임
- 장점: 코드가 100% 재현성을 담보(레이아웃·텍스트·오브젝트) + AI가 "캐릭터/질감"만 보강 → **최대 재현 + 최소 리스크**
- 단점: AI 캐릭터 컷아웃(투명 배경) 필요 → 단색 배경 요청 + 배경 제거(rembg/PIL) 파이프라인 신규
- 샘플 재현 가능성: **70~85%**

### E. 다른 AI 모델 (당장 변경 안 함)
- Gemini(Imagen)/Nano Banana 등은 카드뉴스 스타일 품질↑, 단 API 전환·비용·키 필요 → 조사만 기록
- Pollinations에 `model=flux` 지정 가능(v4flat에서 확인) — 무료 유지 시 최선

## 9. Recommended Architecture

**D. AI + SVG/PIL Hybrid** (레이어 4단 구조)

```
Layer 1 (코드)  배경: 라이트 블루 그라데이션 + 오렌지 halo + 스파클/컨페티 + 프레임
Layer 2 (AI)    캐릭터: 단색 배경에서 생성 → 배경 제거(크로마키/rembg) → 컷아웃 합성
Layer 3 (코드)  오브젝트: 기존 hybrid2 라이브러리 재사용 + 팔레트 교체 + 디테일 강화
                배치: Composition Blueprint 좌표표 기반 링 배열
Layer 4 (코드)  텍스트: CALCMATE 배지 + 상단 제목 존 + 하단 패널 (기존 add_text 재사용)
```

**분기점 판단**: 캐릭터를 "AI 컷아웃"으로 할지 "코드/SVG"로 할지가 유일한 미지수.
- AI 캐릭터: 품질↑ / 일관성↓·컷아웃 파이프라인 필요
- 코드 캐릭터: 일관성↑ / 품질 한계
→ **PoC-2에서 양쪽 시안을 2종 비교**하여 결정.

**기존 자산 재사용** (보호 원칙 내):
- `scripts/_phase5_hybrid_poc_v2.py`의 오브젝트 함수(calendar/clock/document/trophy/calculator/coin/bar_chart)는 전부 재사용 가능
- `add_text`(배지/제목/부제, 2행 분할)는 그대로 사용
- 보호 스냅샷/검증 구조는 그대로 유지, 산출은 `hybrid_poc_v3/` 신규 디렉터리

## 10. CalcMate 3개 주제 적용 설계

### ① 주휴수당 계산기
- **Hero Object**: 캐릭터가 든 **주간 달력(체크 5일)** + **시계** (시간×근무일 = 주휴수당의 인과)
- **Supporting 1~5**: 급여봉투(결과), 동전스택, 계산기, 체크 배지, 상승 화살표
- **캐릭터**: 필요(권장) — 엄지척 포즈
- **배경**: 라이트 블루 + 오렌지 halo + 스파클
- **색상**: 라이트블루 BG / 로열블루 / 오렌지 halo / 그린(체크) / 화이트 카드
- **구도**: 캐릭터 중앙-우측(0.55), 오브젝트 링 좌측(0.15~0.40), 전경 데스크 하단

### ② 퇴직금 계산기
- **Hero Object**: **근속연수 달력 + 서류 묶음(빨간 봉인)** (장기 근속의 증거)
- **Supporting 1~5**: 트로피(보상), 상승 차트(축적), 동전스택, 계산기, 핸드셰이크 배지
- **캐릭터**: 필요 — 설명 제스처(손 펼침)
- **배경**: 라이트 블루 + 오렌지 halo(차분한 톤) + 다이아몬드 데코
- **색상**: 라이트블루/네이비 + 골드(트로피) + 그린(차트)
- **구도**: 캐릭터 좌측 1/3, 오브젝트 우측 아크 배열

### ③ 연말정산 환급액 계산기
- **Hero Object**: **환급 동전(코인 샤워) + 세금문서+돋보기** (환급의 결과)
- **Supporting 1~5**: 계산기, 12월 달력, 상승 화살표, 선물상자, 별 메달
- **캐릭터**: 필요 — 환호/기쁜 포즈
- **배경**: 라이트 블루 + 오렌지 halo + 골드 컨페티
- **색상**: 라이트블루/틸 + 골드(환급) + 레드(봉인) + 그린
- **구도**: 캐릭터 중앙-좌측, 오브젝트 우상단 방사형
